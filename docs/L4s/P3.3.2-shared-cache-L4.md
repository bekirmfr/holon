# L4 — P3.3.2: the shared trustless cache (the differentiator)

**The thesis made operational.** The whole north star is: *pure + content-pinned ⟹ universal
trustless memoization*. P3.3.1 made it **local** (a private `Memo` keyed by `memo_key`). P3.3.2 is
where a result computed once by **anyone** becomes reusable by **everyone** — the open economy's
beating heart. This note scopes it, and surfaces the one decision that needs a human call: *what
"trustless" can honestly mean at this layer.*

---

## The hard truth about "trustless" (THE fork — needs a decision)

"Universal" is already real and free: `memo_key(unit_hash, inputs)` is content-derived and
canonical, so two parties who run the same unit on the same inputs derive the **same key**,
independently, with no coordination. Keys are universal coordinates. That half shipped in P3.3.1.

"Trustless" is the subtle half. To *use* a cached output `V` for key `K` **without trusting whoever
served it**, you need to bind `V` to `K` verifiably. The options:

| how | cost to verify | in scope? |
|-----|----------------|-----------|
| **(a) re-execute** `eval(unit, inputs)` and compare | = the original compute | ✅ buildable now |
| (b) succinct validity proof (zk) attached to `V` | cheap verify, heavy machinery | ✗ a project, not an inch |
| (c) replication / quorum (N parties agree) | network + economics | ✗ networked tier |
| (d) optimistic stake + challenge | economics + challenge window | ✗ P3.4.1+ |

Only **(a)** is mechanical and available today. And (a) has an honest limitation worth stating
plainly: **re-executing to verify costs the same as computing**, so verification-by-re-execution
does *not*, by itself, save compute. What it gives you is **decidability**: you never have to
*trust* a served result — you can always *check* it, and a liar is always caught. Saving compute by
using a result *without* re-running is a separate thing that requires (b)/(c)/(d) — trust earned via
proofs, replication, or reputation — none of which this inch builds.

**So the proposed scope of P3.3.2 is the *verifiable substrate*, not a trust economy:**
universal keys (done) + a **re-execution verification oracle** + a portable, self-describing cache
entry. This is the foundation every later trust mechanism (reputation P3.4.1, proofs, quorum) builds
*on top of* — they all need "given a claimed (computation → result), can I check it?" answered
first. P3.3.2 answers it.

> **DECISION REQUESTED:** confirm this framing — build the verifiable substrate (re-execution
> oracle + portable entry), and let reputation/proofs/quorum layer on later — rather than attempting
> a proof or replication mechanism now. My strong recommendation is yes: (b)/(c)/(d) are each their
> own pillar, and none is meaningful without the substrate.

---

## Why the substrate *is* the thesis (the invariant convergence)

The verification oracle `verify_entry` rests on three invariants at once, and that convergence is
the whole argument:

- **I5 (content-addressing):** `entry.unit_hash` resolves to *exactly one* unit — the claim names a
  specific, immutable computation; it cannot be quietly swapped.
- **I2 (purity/determinism):** a pure unit yields the *same* output every time — so re-execution is a
  *decisive* check (one correct answer to compare against).
- **Totality (no `while`; control = `select` + `fold`):** `eval` always terminates — so
  `verify_entry` always *finishes*. A verification oracle that could hang would be no oracle at all.

A cache entry is trustworthy because, and exactly to the extent that, the VM is pure, total, and
content-addressed. That's the thesis, executable.

---

## The cheap / expensive decomposition (mirrors the Store)

The on-disk `Store` (P3.8.1) does **verify-on-read by re-hashing** — cheap, so always-on. The cache
has the same shape with two tiers:

- **Cheap, always-on — key integrity.** `entry_key(entry) == K`: does the entry's `(unit_hash,
  inputs)` actually hash to the key it's filed under? One BLAKE3 over the canonical encoding. This
  catches a *mis-filed* entry (claims to be computation X, filed under Y) — the analogue of the
  Store's re-hash. It binds the entry to *which computation* without running anything.
- **Expensive, on-demand — semantic correctness.** `verify_entry`: re-execute and canonically
  compare the output. This is the only check that confirms the *output*, and it costs a compute, so
  it is a *consumer choice*, never forced.

Cheap structural integrity is mandatory; expensive semantic verification is opt-in. (In the local
in-memory model, `put` *derives* the key from the entry, so key integrity holds by construction; the
cheap check earns its keep at the **network boundary**, P3.8.2, where a peer supplies the claimed
key.)

## Proposed surface

### Core — extend `memo.rs` (reuses the private `encode_value` + `memo_key`)

```rust
/// A portable, self-describing memo: a claim that running `unit_hash` on `inputs` yields `output`.
/// Self-describing precisely so a recipient who didn't compute it can verify it (unlike the bare
/// `Value`s of the private local `Memo`, which trusts itself).
#[derive(Clone, Debug, PartialEq)]
pub struct CacheEntry {
    pub unit_hash: Hash,
    pub inputs: Vec<Option<Value>>,
    pub output: Value,
}

/// Cheap: the universal key this entry must be filed under = memo_key(unit_hash, inputs).
/// (Output is NOT in the key — the key names the *computation*, not its result.)
pub fn entry_key(entry: &CacheEntry) -> Result<Hash, EncodeError>;

/// Expensive, decisive: the trustless oracle. True iff `unit_hash` resolves, the unit is *pure*
/// (only pure outputs are stable enough to cache), and re-executing yields `output` —
/// compared **canonically** (NaN/±0.0 folded exactly as memo_key folds inputs, so verification
/// agrees across machines). Fail-closed: unresolvable or impure ⇒ false.
pub fn verify_entry(entry: &CacheEntry, resolver: &impl Resolver) -> bool;
```

### Host — `SharedCache` near `Memo`

```rust
pub struct SharedCache { entries: BTreeMap<Hash, CacheEntry> } // K = entry_key → entry

impl SharedCache {
    pub fn new() -> Self;
    /// Insert under its derived key. Dumb on purpose: the cache itself is *untrusted* — trust is
    /// established on read, not write. (Key integrity holds by construction here.)
    pub fn put(&mut self, entry: CacheEntry) -> Result<Hash, EncodeError>;
    /// Fast path — the raw entry, unverified. Caller trusts the source (or will verify).
    pub fn get(&self, key: &Hash) -> Option<&CacheEntry>;
    /// Trustless path — the output, but only if it re-executes correctly against `resolver`.
    pub fn get_verified(&self, key: &Hash, resolver: &impl Resolver) -> Option<Value>;
}
```

FCIS split is identical to P3.3.1: pure key+verify logic in core, the state cell in host.

## Forks & resolutions

1. **What "trustless" means** → re-execution oracle (a); proofs/quorum/stake deferred. *(The
   decision above.)*
2. **Cheap-mandatory vs expensive-optional verification** → both: `entry_key` (cheap, structural) +
   `verify_entry` (expensive, semantic). Mirrors the Store.
3. **Entry payload** → self-describing `{unit_hash, inputs, output}`, not a bare `Value`. A portable
   entry *must* carry enough to verify; the local `Memo` stays bare and self-trusted (kept separate —
   different role, no redundant merge).
4. **Where verify lives** → core (pure function of entry + resolver), in `memo.rs` to reuse the
   private canonical encoder. Host holds only the state cell.
5. **Output comparison** → **canonical** (via `encode_value`), not `Value`'s `PartialEq`. Grounded:
   `eval` can emit `NaN` (overflow→`inf`→`divide(inf,inf)`), and NaN bit-patterns aren't portable
   across machines; canonical comparison is what makes verification machine-independent — and it
   reuses the exact folding `memo_key` already applies to inputs.
6. **`put` trust posture** → dumb insert (cache is untrusted; verify on read). Aligns with
   trustlessness: don't pretend the store is honest; check what you read.

---

## Explicitly deferred (so the boundary is clean)

- **Compute-savings-without-trust** (use `V` without re-running): needs reputation (P3.4.1), proofs,
  or quorum. The substrate makes all three possible; none is built here.
- **Network transport / peer-supplied keys**: P3.8.2 (networked CAS). The cheap `entry_key` check is
  built now precisely so the network boundary has its integrity primitive ready.
- **Purity memoization** (caching `is_pure(unit_hash)` since it's content-determined): an
  optimization, not correctness. Later, if `verify_entry` profiles hot.
- **Overflow saturation** (should pure arithmetic refuse `inf`?): a separate primitive-set question;
  canonical comparison handles the consequence either way.

## Test plan (core ~5, host ~3 ⇒ target 153 core+host total ≈ 182)

Core: round-trip key (`entry_key` == `memo_key` of the same fields); `verify_entry` true for an
honest entry; false for a tampered output; false for an unresolvable unit; false for an *impure*
unit; **NaN output verifies** (the canonical-comparison guard — the test that proves machine
independence). Host: `put`→`get` round-trips; `get_verified` returns the output for an honest entry;
`get_verified` returns `None` for a tampered one (the trustless-read path catches the liar).

## One-line summary

P3.3.2 = **universal keys (done) + a verification oracle + a portable entry**, resting on
purity + totality + content-addressing. It makes any memo *checkable by anyone* — the trustless
substrate every later trust mechanism stands on. It does **not** yet let you skip compute on a
stranger's word; that is reputation/proofs/quorum, and each is its own pillar.
