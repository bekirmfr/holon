# P1.3.2 — Parametric types · Level-4 design (rev. 5)

> **Companion to `PLAN.md`.** Opens the fork §5 / P1.3.2 deferred as *"the single largest jump in
> checker complexity"* — scoped so the **declaration algebra is minimal-complete** and the **checker
> stays structural** (equality + `Any` wildcard, recursive): no inference, no subtyping. **Pre:** P1.6
> (encoder), P1.3.1 (validate), P1.5.1 (encapsulation). **Inv:** I5 (changes the hash preimage —
> identity), §5 (extended, not replaced), I4 (the typed interface contract), I1 (catalog stays core's).
> **Effort:** M–L — the **type language lands in one inch**; the value constructors are earned behind it.
>
> *Rev. 3 collapses the type layer into a single inch (the whole composed-type-expression language)
> and re-scopes the remaining inches to the value-constructor layer — the type cost is paid once, by
> making `Type` recursive, whether the enum then carries one constructor or three.*
>
> *Rev. 4 folds in the invariant audit (§9): nothing is compromised; I4/I9 strengthen; the one new
> must-do is a fail-closed decode-depth bound (§3, gated in inch 1); two I5 canonicalization calls and
> the §5-under-pressure note are recorded; the I1 "walk-to-render, never to-judge" line is in inch 4.*
>
> *Rev. 5 — **inch 1 landed (green)**, re-scoped to `List<T>` only: grounding showed the de-Copy is
> paid by `List` alone and a second version bump is free pre-release, so `Product`/`Sum` *types* fold
> into their constructor inches (2, 3) rather than landing speculatively. §8 updated.*

## 0. The decision: a complete *declaration* algebra over a structural checker

The flat type system (`Number, Boolean, Text, List, Effect, Any`; a 1-byte tag;
`compatible = dst==Any || src==Any || src==dst`) is §5 verbatim, deferred on purpose. The trigger is
real: a claimed *programming language* needs composable type expressions — strict-everything-to-flat
-literals is machine-language-flavoured. The editor wants declarable, composable port types, and
`map`-produces-`List` / `get`-returns-`Any` is the coarseness biting.

**Two separations organize the whole design.**

*First — the declaration algebra vs the checker.* The algebra (what a port type can *say*) is made
**minimal-complete**: enough to declare any first-order data shape, nothing redundant. The checker
(how two types compare) stays **structural**: equality + the `Any` wildcard, made recursive. No
inference, no unification, no subtyping — the property §5 valued, preserved exactly, just nested.

*Second — the type language vs the value constructors (this drives the build order).* The type
**language** — declaring, encoding, checking, and bottom-up-promoting composed types — is **one cheap
thing that lands whole now**, because its only real cost is making `Type` recursive, paid once. The
value **constructors** — actually *building and evaluating* a `Pair` or a `Sum` value — are a
**separate, earned-per-use layer**, because each adds runtime machinery (and `Sum` a genuine new value
kind). You can have the entire composable type language — every unit declaring rich contracts, checked
and promoted — before a single `pair` constructor exists. So we build the language now and light it up
with constructors as each is used.

This keeps *strict literals* (a value-construction virtue — `const` builds scalars only, never infers;
a list is *constructed*, its type *declared*, never guessed) and *composable types* (an
interface-declaration virtue) together, not in tension. Strict literals **and** composable types.

The spine: *compose a small orthogonal set deeply* — the system's ethos — applied to types. Two
generators (product, sum) plus one ergonomic recursive primitive (`List`) generate every algebraic
data type. Take the **composition**; refuse the **machinery** (subtyping, inference).

**Why now.** Port types are in the hash preimage (`port_type_changes_hash`) — the most
identity-sensitive change there is. The corpus is **empty** (no registry has published; the editor
mints only ephemerally), so this is the *settle identity before you mint* moment (the child-order
precedent). Doing the encoding before composites multiply costs only the work.

## 1. The minimal-complete algebra

**Atoms (5) — the irreducible leaves.** `Number`, `Boolean`, `Text` (the three *scalar* literals,
exactly what `const` constructs from text); plus `Any` (top / wildcard / escape hatch) and `Effect`
(the settled-request type). Not constructible, already in the system.

**Constructors (3).**
- **`List<T>`** — homogeneous sequence. (Derivable as `µX. Unit + T×X`, but kept primitive for
  ergonomics, and because the *value* already exists.)
- **`Product([T…])`** — positional, n-ary tuple. *Both.* `Pair<A,B>` = `Product([A,B])`; **`Unit` =
  `Product([])`** (the empty product — "no information" — so Unit needs no atom of its own).
- **`Sum([T…])`** — positional, n-ary tagged union. *Either.* `Either<A,B>` = `Sum([A,B])`;
  `Option<T>` = `Sum([T, Product([])])` (T, or nothing).

**Why these and no more (the completeness claim).** Product (grouping) and sum (choice) are the two
*independent* generators of algebraic data types — neither derives the other, together they generate
all of them. So the named compound types are **derived sugar, not primitives**:

| Named type | Is | Status |
|---|---|---|
| `Pair<A,B>` | `Product([A,B])` | sugar |
| `Unit` | `Product([])` | sugar (the 0-ary product) |
| `Dictionary<K,V>` | `List<Product([K,V])>` | **derived — not a primitive** |
| `Option<T>` | `Sum([T, Product([])])` | sugar |
| `Result<T,E>` | `Sum([T, E])` | sugar |
| records, trees, ASTs, JSON | recursive sums of products | derived |

**N-ary positional** (not strictly binary `Pair`/`Either`) is the representation choice: it matches the
system's existing positional vectors (ports, edges, children are count-prefixed lists), lets a
record-shaped type be one node, and makes `Unit` the empty product for free. Binary `Pair`/`Either`
are just the 2-ary cases.

**The line that keeps the checker structural.** `Product`/`Sum` are **positional** — compared by
*arity + position*, never by *field name*. That keeps them inside the structural checker.
Named-field records with width/depth subtyping, and function types `A→B` (variance + inference), are
the two things that do *not* fit — deferred (§7).

## 2. Representation — and the one real ripple

```rust
pub enum Type {
    Number,
    Boolean,
    Text,
    Effect,
    Any,
    List(Box<Type>),     // List<Any> is the bare/legacy list
    Product(Vec<Type>),  // positional tuple; Product(vec![]) == Unit
    Sum(Vec<Type>),      // positional tagged union
}
```

**`Type` loses `Copy`** (a `Box`/`Vec` can't be `Copy`) → `Clone`-only. This is *the* cost of the type
language, and it is paid **once** — having one recursive variant or three is the same de-Copy, plus a
few match arms each. It ripples to every `Type`-by-value site, all compiler-caught:
`compatible(&Type, &Type)`; `Encoder::ty(&Type)`; `Port.ty` reads in `validate`/`kind`/`catalog`/
`encapsulate` take `&` or `.clone()`; the bridge `WType` mirror. The clones are cheap. That breadth —
not the design — is what §5 meant by "the largest jump," and it's why all three constructors land
together: paying it for `List` alone would bank a third of the reward for the whole cost.

## 3. Encoding — the identity-critical part

`Encoder::ty` pushes one byte (`t.tag()`) today; `Decoder::ty` reads one (`from_tag`). Make both
recursive, count-prefixing the n-ary nodes exactly as inputs/edges already are:

```rust
// encode
fn ty(&mut self, t: &Type) {
    self.buf.push(t.tag());
    match t {
        Type::List(inner) => self.ty(inner),
        Type::Product(ts) | Type::Sum(ts) => { self.u32(ts.len() …); for x in ts { self.ty(x) } }
        _ => {}
    }
}
// decode mirrors it: tag → (List: one inner) | (Product/Sum: u32 count then that many) | scalar
```

Scalar tags are unchanged, so a unit with **no** compound type encodes byte-identically to today.

**`ENCODING_VERSION` → 2.** The scheme changed shape, so *"bump whenever the encoding changes in any
way"* applies. Empty corpus ⇒ nothing to migrate, no v1 hash to collide with — the bump makes
cross-scheme collision impossible by construction. (Child-order *restricted* the encoder and kept v1;
this *extends* it, so it bumps.)

**Bare list = `List<Any>`.** The catalog/editor write `List(Box::new(Any))` wherever they wrote
`List`. No separate bare variant; an "unparametrized list" simply *is* `List<Any>`, compatible with
any `List<T>`.

**Bound the decode depth (fail-closed — the one new security risk).** Today's `ty()` is flat: one byte,
no recursion. A *recursive* decoder over **untrusted bytes** (the store ingests blobs from anywhere)
can be handed a hostile preimage that nests thousands deep — `List<List<List<…>>>`, or a `Product`
claiming a vast count of nested children — and **blow the stack** decoding it: a denial-of-service on
the very function (`decode_preimage`) that verifies untrusted blobs. The decoder already refuses to
pre-allocate from stream-supplied counts (a lying length hits `UnexpectedEof` fast), but *depth* is a
new dimension that instinct doesn't yet cover. The fix is small and fail-closed: a **maximum type
nesting depth**, returning a `DecodeError::TypeTooDeep` past it rather than recursing. This belongs
**in inch 1**, next to the recursive `ty()` — not a later hardening.

## 4. The checker — §5 lifted, not replaced

```rust
pub fn compatible(src: &Type, dst: &Type) -> bool {
    use Type::*;
    match (src, dst) {
        (_, Any) | (Any, _)              => true,                 // the wildcard, at this level
        (List(a), List(b))               => compatible(a, b),
        (Product(a), Product(b))
            | (Sum(a), Sum(b))           => a.len() == b.len()
                                            && a.iter().zip(b).all(|(x,y)| compatible(x,y)),
        _                                => src == dst,           // scalar equality
    }
}
```

Structural recursion + an `Any` wildcard at every level. No subtyping (`Product`/`Sum` require **equal
arity** — positional, so no width-subtyping), no inference, no type variables. Examples:
`List<Any> ⟷ List<Number>` → true (constructed lists stay permissive — correct); `List<Text> ⟷
List<Number>` → false; `Pair<Number,Text> ⟷ Pair<Number,Any>` → true; `Pair<A,B> ⟷ Product([A,B,C])` →
false (arity). "Polymorphic units without a unification checker" (§5's goal) still holds — `compatible`
carries no state, just recursion.

## 5. The interface contract & bottom-up promotion (already the architecture)

**Not new mechanism** — it's I4 made composable by §§1–4, named because it's the property the editor
was reaching for, and it all lands inside the one type-language inch.

- **The contract already exists.** Every unit declares typed ports — `inputs: Vec<Port>` + `output` —
  and that interface is *in the hash* (I4, the frozen public contract). Primitives declare it
  (`interface_of`); composites have it **derived then frozen** by `derive_and_freeze`.
- **Composable contracts fall out.** A `Port.ty` is a `Type`; once `Type` is recursive, a port can
  declare any composed type (`List<Pair<Number,Text>>`). Nothing added — ports already hold a `Type`.
- **Bottom-up promotion falls out.** `derive_and_freeze` already copies each unbound inner port's `ty`
  to the promoted boundary port, and the exposed inner output's `ty` to the composite output. With
  `Type` cloned (the de-Copy from §2), that copy carries the **full composed type upward, faithfully**
  — a composite over `List<Number>` inner ports promotes a `List<Number>` boundary input, no new code.
- **The one honest limit.** Faithful through *declared* types; at a **polymorphic** unit
  (`map`/`fold`/`get`, statically `List<Any>`/`Any`) the precise type needs inference, so it promotes
  as `Any`. Same line as the rest of the fork.
- **Structural, never nominal.** A "Person" is a *label* over a structural `Product`, cosmetic like a
  node name (I5) — not a distinct type. Content-addressing requires structure = identity: two
  structurally-equal types are the same type. (Multi-*output* composites are an orthogonal deferral.)

## 6. The two layers — why the language lands whole and the constructors stage

The type cost is in §2: making `Type` recursive, paid once. Everything else in the type language —
recursive encode/decode (§3), recursive `compatible` (§4), composable contracts and promotion (§5) —
is a few arms over that one recursive shape, identical work for one constructor or three. So the
**type language is one inch**: declare, encode, check, and promote any composed type, with no behaviour
change to existing units.

The **value constructors** are a different layer, and unequal in cost — which is exactly why they
stage:

- **`List` value** — already exists. `List<T>` is a pure *type* refinement: nothing to build.
- **`Product` value** — **type-mostly**. A product value is a fixed bundle and eval is untyped, so a
  `Product([A,B])` value can ride the existing `List` value, with a `pair`/`tuple` constructor that
  builds a list value but *declares* a `Product` output type. The static type distinguishes it; eval
  doesn't need to. ≈ as cheap as `List<T>` (type + one constructor, no new `Value`).
- **`Sum` value** — the genuine new value kind. A tagged union value must carry **which variant** — a
  tag — which can't ride a bare list without a convention or a `Value::Sum`. So it adds a runtime tag +
  constructor(s) + `compute` + value-encoding (the memo key).

Building a `pair` with nothing yet consuming products would be dead code; declaring and checking
`Product` types is not. So the *types* land now (the language); the *constructors* land when something
constructs or evaluates such a value (the use). Until a constructor introduces a `Product`/`Sum`-typed
port, those types are available — a unit can declare one directly through the bridge — but the genesis
leaves don't produce them yet; each constructor lights its type up end-to-end.

## 7. Deferred, with triggers (recorded, not built)

- **Named-field `Record` + width/depth subtyping** — the single most expensive item; it leaves the
  structural checker for subtyping. Positional `Product` covers structured data without it. **Trigger +
  explicit decision** to accept subtyping required; until then a "record" is a labeled `Product`
  (labels cosmetic, §5/I5).
- **Function types `A→B`** — variance + inference; the real generics that would type `map`/`fold`/
  `get` precisely. Not needed for *data* declaration. Stays deferred; those leaves stay `Any`.
- **`Dictionary` as a primitive value kind** — stays **derived** (`List<Product([K,V])>`). Trigger:
  a concrete need (keyed lookup at scale) the list-of-pairs representation genuinely cannot serve.

## 8. Inch sequence (build order — the language first, then the constructors)

1. **The `List<T>` type-expression language** — **DONE (green; 212 native / 12 wasm-target).**
   Grounding revised this from "all three type constructors" to **`List<T>` only**: the de-Copy is
   paid by `List` alone, and a second `ENCODING_VERSION` bump is free pre-release, so landing
   `Product`/`Sum` *types* before their constructors would be machinery ahead of use. Delivered:
   recursive `Type` (`List(Box<Type>)`, `Clone` not `Copy`), recursive encoder/decoder,
   `ENCODING_VERSION=2`, fail-closed decode depth bound (`MAX_TYPE_DEPTH`, `DecodeError::TypeTooDeep`),
   recursive `compatible(&Type,&Type)`, catalog as `List<Any>` (behaviour-identical), bottom-up
   promotion carrying composed types, bridge flat (`List<Any>`). *Gate met:* all 208 prior tests green
   under the re-encoding (`List<Any>` ≡ old bare `List`), plus `list_type_round_trips`,
   `bare_list_encodes_as_list_any`, `deep_type_is_rejected`, `compatible_is_structural`. Nothing
   persisted ⇒ the version bump was free; no genesis manifest to re-pin.
   *Optional follow-on (uses the language, changes checker behaviour, separately tested): tighten the
   monomorphic leaves — `sum : List<Number>`, `join : List<Text>` (`sum_refuses_text_list`).*
2. **`Product` (type + `pair`/tuple constructor, value rides `List`)** *(core)* — adds the `Product`
   `Type` arm + encode/decode + `compatible` arm (a free `v3` re-bump, empty corpus) **together with**
   its constructor, so it lands used, not speculative. A unit can now *produce* a `Product`-typed port,
   so composites promote product contracts bottom-up; `Dictionary` becomes usable as `List<Pair>`.
   Earned when something constructs a pair (the correlation `[token, reply]` is the standing example).
3. **`Sum` / `Option` (type + the new tagged value kind)** *(core)* — adds the `Sum` `Type` arm
   alongside the runtime tag, constructor(s), `compute`, value-encoding. Earned when a variant or
   optional *value* is constructed/evaluated — the sentinels today (`head []→None`, `index_of →-1`)
   are the smell.
4. **Bridge + editor** *(after core settles)* — `WType` gains the recursive `List`/`Product`/`Sum`
   variants (serde-mirrored, `from_core`/`into_core` recurse); `holon.ts` `WType` becomes the matching
   recursive union; type-as-colour renders a composed type (hue + inner in the label); boundary-input
   fields use the composed type (scalars get fields, non-scalars "wire in", now precise). The
   originally-requested boundary-input-fields inch lands cleanly on top. **I1 discipline:** the editor
   *walks* a composed type to **draw** it (colour, label, fields) but never to **judge** it — the
   moment a compatibility decision is reimplemented in TS to save a round-trip, the one-decider
   invariant breaks. Walk to render, ask core to decide.

Inch 1 lands the language and settles identity — load-bearing. Inches 2–3 are the value layer, each
lighting up one constructor when its use arrives, value-cost rising. Inch 4 is reach. `Dictionary`
stays derived throughout; `Record`-with-names and function types stay deferred.

## 9. Invariants & proofs

*Headline of the invariant audit: nothing is compromised. The change is consistent with every
invariant; I4 and I9 (a richer interface is more informative to inspect) get **stronger**; I2/I3/I6/I8
are untouched (types are static inline metadata — eval stays pure, no by-hash reference is added, the
effect axis is orthogonal). I5 and §5 hold, each with a thing to keep on purpose, below; and there is
exactly one new must-do — the §3 depth bound.*

- **I5 (identity).** The encoding change is *the* care point — done now, empty corpus, version bumped,
  genesis re-pinned; `encode∘decode = id` and the full suite under re-encoding are the guard. Two
  canonicalization calls to make **deliberately**, because they run *opposite* to the child-order
  precedent:
  - **Constructor argument order is semantic — in the hash, NOT canonicalized.** `Pair<Number,Text> ≠
    Pair<Text,Number>`; `Sum([T, Unit])` (tag 0 = present) genuinely differs from `Sum([Unit, T])`. So
    position is *meaning*, encoded verbatim — the inverse of child order, which was *presentation* and
    had to be normalized away. (Recorded so a future reader doesn't "fix" it by sorting.)
  - **One representation per type — canonical by construction, no new normalization pass.** `bare
    List = List<Any>`, `Unit = Product([])`, and **n-ary positional** (not binary `Pair`-nesting) mean
    a 3-tuple is `Product([A,B,C])` with no aliasing as `Pair(A, Pair(B,C))`. Each semantic type has
    exactly one byte form — which is a quiet second reason to prefer n-ary over binary: binary would
    re-open the aliasing question child-order had to solve.
- **§5 (the rule) — preserved now, but the invariant under pressure.** Extended, not replaced —
  equality + `Any` wildcard, recursive over positional constructors. "No unification checker" holds by
  construction: `compatible` carries no inference state. The honest risk isn't *this* change; it's that
  it **lowers the activation energy for the next one** — once interfaces can say `List<Pair<…>>`, the
  pull toward precise `map`/`fold` typing (needs type variables → inference) and named-record subtyping
  (needs width/depth → a real checker) gets much stronger. Both are deferred in §7; holding that line
  is now a **discipline to defend**, not an automatic property. The type system just became expressive
  enough to tempt the exact machinery §5 spent its budget avoiding.
- **I4 (the contract).** Already the architecture; the language inch makes it composable and its
  bottom-up promotion carry composed types faithfully (§5), with `Any` at polymorphic units.
- **I1 (one decider).** The catalog and the recursive `WType` are *derived* from core, never
  hand-written in TS — the `interface_of` discipline.
- **Fail-closed.** `Any` is permissive but explicit; unknown tags still hit `DecodeError::BadType`; a
  declared mismatch (`List<Text>` into `List<Number>`, wrong-arity `Product`) is caught at wire time,
  earlier than the old runtime `None`. Strictly more is caught, nothing less. **The one new must-do:**
  recursive decoding of untrusted bytes is a fresh stack-exhaustion surface — bound the type nesting
  depth in inch 1 (§3), `deep_type_is_rejected` in the gate. Reject deep, don't crash.
