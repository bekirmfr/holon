# State cell — Level-4 design (P2.6.1, the one fenced place purity ends)

> *crate:* **`holon-core`** (the leaf split + classification refinement) **+ `holon-host`**
> (storage, the round) · *pre:* Fork B reconciliation, `P2.4.1`-deploy · *inv:* `§7` /
> `I7` / `I5` · *effort:* **M**
> *Pinned:* **two-leaf** mechanism (`store_read` driver-like + `store_write` sink-like;
> the editor presents one "Store" widget over the pair) · **one anonymous cell** (keys
> deferred).

---

## 0. The realization: state needs almost no new machinery

A cell **read** sources a value the host holds → that is a **driver** (host-supplied;
design mode scripts it). A cell **write** commits a value the host persists → under
Fork B that is a **sink** (its output *is* the new value; its capability is
`StateWrite`; the host performs it by *storing* instead of sending). The cell is the two
things the system already has, and three hard problems dissolve at once:

- **No graph cycle.** A counter is read → +1 → write, which *looks* like a loop
  (`cell → … → cell`). But read and write are **separate leaves**, so there is no edge
  from write back to read — the feedback goes through the host's storage *between
  rounds*. The host's storage **is** the register that breaks the cycle. `validate` is
  untouched; no special acyclicity exemption.
- **`eval` is untouched.** The write reaches the output as an ordinary Fork-B sink
  (output-carried), exactly like an email — no observer hook, no intermediate exposure.
- **The `(Model, Cmd)` round falls out.** The host's storage is the `Model`; a
  `StateWrite` is just an effect whose `perform` *loops back* into storage instead of
  exiting to the world; a `StateRead` is an input sourced from storage.

State is not a new boundary. It is the driver/sink boundary, read **and** written by the
same host, with storage as the only addition.

## 1. The two leaves (one anonymous cell)

| leaf | capability | side | pure `compute`? | design mode | deploy |
|---|---|---|---|---|---|
| `store_read` | `StateRead` | input (sourced) | no — sourced | mocked (scripted held value) | host injects storage |
| `store_write` | `StateWrite` | output (carried) | **yes — identity** (Fork B) | evaluates directly | host performs ⇒ store |

Both are kind `State` (the doc's "one explicit state primitive"), distinguished by the
capability they carry — `StateRead` vs `StateWrite` were always two capabilities, and
now the host acts on the difference. **One anonymous cell:** the host holds a single
slot; the lone `store_read` sources it, the lone `store_write` commits to it — no key.
Multiple keyed cells need `StateWrite(key)` (a parameterized capability resource),
deliberately deferred. The **editor** (P4) presents a single "Store" node over the pair;
the *mechanism* stays two clean leaves.

---

## 2. The round (`Model`, `Cmd`) — snapshot then apply

```
snapshot storage ─▶ source store_read = snapshot ─▶ eval settles ─▶ perform output-side
 (the round's Model-in)   (input substitution)        (one decider)     effects:
                                                                          StateWrite ⇒ store  (loop-back, the Model-out)
                                                                          egress     ⇒ send   (exit, the Cmd)
```

Reads see the **round-start** snapshot; writes apply at **round-end** — the atomic Elm
`update(old) → (new, cmds)`. The snapshot also resolves the obvious borrow knot: the
read-substituting resolver borrows the snapshot (a local clone), so the host stays free
to mutate storage when the round applies. Across rounds the host threads storage and the
counter climbs — *"`Store` remembers across firings."* Eager ⟹ each effect performed
once on the settled value; quiescence is free; no debounce.

---

## 3. The classification refinement: input-side vs output-side

The honest split is **sourced** (the host supplies it) vs **performed** (the host
executes it), and the capability layer already carries it:

```
is_sourced(cap):  Clock | NetworkIngress | FileRead | SecretAccess | Random | StateRead
performed (¬sourced):  NetworkEgress | FileWrite | Spawn | StateWrite
```

Two existing predicates sharpen, neither invented:

- **`mock_of`** (design mode) mocks the *sourced* side — so the rule stops being "kind
  == Driver" and becomes "has a sourced capability," and `StateRead` joins the drivers
  (a scripted held value). The output side (sinks **and** `StateWrite`) stays pure /
  output-carried — no mock.
- **`fire`** (deploy) performs the *output* side — `!cap.is_sourced()` instead of
  `kind == Sink`, so `StateWrite` joins the performed effects. Backward-compatible:
  `NetworkEgress` is non-sourced, so the existing host tests are unaffected.

`StateRead` ≠ `StateWrite` was always in the capability model; this inch just lets the
two ends be sourced and performed respectively, which is what the doc's "consequences
exit at the bottom, time enters at the top" always meant.

## 4. Build order

1. **Core (pure):** split `"store" => [StateRead, StateWrite]` into `"store_read" =>
   [StateRead]` and `"store_write" => [StateWrite]`; give `store_write` an identity
   `compute` (Fork-B sink); add `Capability::is_sourced`; refine `mock_of` to the
   sourced predicate. Update the six `"store"` test sites to the two leaves.
2. **Host:** a single-slot `storage` (the `Model`); a read-substituting resolver
   (injects the snapshot for `store_read` leaves); `fire` performs `!is_sourced`; a
   `round` that snapshots → fires → applies (`StateWrite ⇒ storage`); the multi-round
   counter.

Core first (pure, in the comfortable half); the host round second.

## 5. Tests

- *core:* `store_read_is_mockable` (sourced ⇒ a design mock); `store_write_is_pure_
  identity` (a Fork-B sink, `compute` runs it); `state_read_graph_design_evals` (a
  read-bearing graph runs in design mode via the mock); the existing replayability test
  holds (a `store_read`/`store_write`-bearing closure is non-replayable).
- *host:* `counter_remembers_across_firings` — the load-bearing one: three rounds drive
  storage 0→1→2→3; reads see the prior write; `eval` performed none of it.

---

## 6. Deferred (recorded)

- **Keyed / multiple cells** — `StateWrite(key)` / `StateRead(key)`: the parameterized
  capability resource. One anonymous slot until then.
- **`P2.6.2` transactional read-then-write** — atomic conditional update (no write-skew);
  composed *from* this cell (the donor primitive).
- **`P2.6.3` replay / fork / pin** — value-not-hashed (already true; runtime `Value` was
  never in the preimage) + copy-on-write fork; the non-replayable half already holds via
  `is_replayable`.
- **External `drive`** — sourcing real driver values (`Clock`, ingress) from the world;
  state reads its slot, not the world, so it needs no external IO.
- **B fan-out** — a graph with *both* a `StateWrite` and an egress is two effects ⇒
  `List[Effect]` (representation B). Under A a round carries one output-side effect.

---

## 7. Invariant check

`§7` — state is the **single fenced** place purity ends; a cell-bearing closure is
non-replayable, by inspection. `I5` — `eval` untouched (write is output-carried, read is
substituted); the one evaluator is unchanged. `I7` — effects stay at the edges:
`StateRead` enters at the top (sourced), `StateWrite` exits at the bottom (performed).
FCIS — the host is still the only impurity; it now *stores* as well as sends, but
`perform` remains the sole impure operation. The cycle that looked like it needed a
`validate` exemption is broken by storage between rounds, not by a rule.
