# L4 — P3.8.2: networked transport (mostly already done)

**The finding first.** I expected "networked CAS" to be a substantial inch. Grounding it shows the
opposite: **content-addressing has already secured the network boundary.** This note applies the
discipline — *name the property the new layer would add; show whether the system already provides
it* — and the answer is "almost entirely yes." What's left is one tiny gap and a pile of deferred
plumbing.

## What a network boundary needs, and what already provides it

A stranger hands you data and claims it's `X`. Trustless transport = you can check the claim against
content, never against the stranger. Three cases:

| you fetch… | the check that makes it trustless | already built? |
|------------|-----------------------------------|----------------|
| a **unit** (bytes claimed to be hash `H`) | decode, re-hash, reject if `≠ H` | **YES** — `decode_verified(key, bytes)`, used by *every* `Store::get` already (a network `Store` reuses it verbatim) |
| a **cache key** (entry claimed to be at key `K`) | `entry_key(entry) == K` | primitive **YES** (`entry_key`); the *ingest check using it* — **NO** (the one gap) |
| a **cache result** (output for `K`) | `verify_entry` (re-execute) | **YES** — the trustless read, `get_verified` |

A malicious peer can only give bytes that hash to their own name or bytes that don't (rejected); it
**cannot** forge content under the right name without breaking BLAKE3. No identity, no trust in the
peer — exactly the thesis. The architecture did the work; this is the discipline paying off.

## The one genuine gap: the cache has no trustless *ingest*

`SharedCache::put` *derives* the key (`entry_key`) and inserts — so it can't model a peer **supplying
a claimed key**, and can't reject a mis-keyed entry. The `Store` got its verify-on-read
(`decode_verified`) at birth (P3.8.1); the cache's `put` derived keys (P3.3.2), so it never grew the
analogue. The P3.3.2 L4 explicitly promised `entry_key` would "earn its keep at the network boundary,
where a peer supplies the claimed key" — this is that boundary. The fix brings the cache to parity
with the `Store`:

```rust
/// Trustless ingest of a peer-supplied entry claimed to live at `claimed_key`. The cheap
/// structural check — does the entry actually hash to the key it's offered under? — rejecting a
/// mis-keyed entry (a peer lying about *which computation* an entry is for). The cache's analogue
/// of the Store's verify-on-read. Semantic correctness (the *output*) is still the consumer's
/// `get_verified` (re-execution) — ingest is the cheap admission gate, not the trust decision.
pub fn ingest(&mut self, claimed_key: Hash, entry: CacheEntry) -> Result<(), CacheIngestError>;
```

Two tiers, same as everywhere: **cheap structural admission** on ingest (`entry_key == claimed_key`),
**expensive semantic trust** on read (`get_verified` re-executes). The store stays untrusted; a
structurally-valid but wrong-output entry is admitted by `ingest` and *caught* by `get_verified`.

This is *exposure*, not new machinery — surfacing a check the foundation already provides
(`entry_key`) at the boundary it was designed for. It's transport-agnostic and adversarially testable
**without any network** (it's also how you'd safely import a cache dump or accept an entry by any
means), so it earns its place independent of when a wire lands.

## Explicitly deferred — and *not* building these now is correct, not a gap

- **The wire itself** (TCP / HTTP / libp2p, async runtime, peer discovery, framing). Its
  **security is already handled** by the table above, so it is *plumbing* — and it's a different kind
  of work: a large dependency surface (tokio/hyper/…), async I/O, untestable in this crate's pure
  unit-test discipline. It belongs to a deployment/infra phase, behind whatever transport a real
  deployment picks. Building it now would be premature and would drag the whole project's dependency
  and testing posture sideways for no security gain.
- **A `Remote`/`Peer` trait.** Speculative until a real wire impl needs it (no caller today). Earn the
  abstraction when the second transport appears — not before. *(Same YAGNI lens that killed the
  Store→Resolver adapter.)*
- **A networked `Store` impl.** When built, it's a `Store` whose `get` fetches bytes over the wire and
  calls the **existing** `decode_verified`. No new trust logic — it inherits the contract.

## Why this isn't under-scoping

The temptation is to "build the network" to make P3.8.2 feel substantial. But the honest accounting
is that the trustless *boundary logic* is the valuable part, and it's almost entirely already present;
the transport is mechanical and its safety is free. Shipping the one missing check (cache ingest) and
*documenting* that the rest is secured + deferred is the disciplined outcome — the same way dropping
identity was. The system was designed so that transport is nearly trivial; this inch confirms that and
closes the last small asymmetry.

## Test plan (host-only, ~3 ⇒ ~194 total; core unchanged at 156)

`ingest` accepts a correctly-keyed entry, after which `get`/`get_verified` behave as for a local
`put`; `ingest` **rejects** a mis-keyed entry (the peer-lied-about-the-key case → `CacheIngestError`);
an ingested entry with the right key but a *wrong output* is admitted by `ingest` yet returns `None`
from `get_verified` (the two tiers — cheap admission, expensive trust — both exercised).

## DECISION REQUESTED

**(A)** Confirm the scope: build **only** `SharedCache::ingest` (the cache's trustless-ingest, the one
genuine gap, fulfilling the P3.3.2 design promise and reaching Store-parity), and **defer** the wire,
the `Remote` trait, and a networked `Store` impl as infra whose security is already handled.

**(B)** Or, if even `ingest` reads as premature without a wire to call it: build **nothing**, and
record P3.8.2 as "transport-trustlessness already delivered by content-addressing; wire deferred to an
infra phase," leaving `ingest` for whenever a real sync path appears.

My recommendation: **(A)** — `ingest` is small, fulfills an explicit prior design promise, closes a
real Store/cache asymmetry, is valuable beyond networking (safe import), and is adversarially testable
now. The wire genuinely is later infra, and saying so plainly is the right call.
