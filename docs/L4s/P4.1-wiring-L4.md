# Wiring + the wire-time type check (L4)

**Status:** second P4.1 inch — connect placed nodes, with the type check enforced as you wire.
Delivered in two steps: the `compatible` bridge (Rust, test-confirmed) then the wiring UI (TS,
browser-confirmed).

---

## 1. The rule lives in core, not the editor (I1)

A wire is legal iff the upstream output type and the downstream input type are **`compatible`** — and
that rule is core's `validate::compatible`: `dst == Any || src == Any || src == dst`. The editor's
`isValidConnection` asks **core** (across the bridge), it does not reimplement the rule in TypeScript.

This is the one decision worth defending, because the rule is *trivial today* (`a === b || either Any`)
and a TS copy is one line — the strongest possible pull toward "just inline it." We don't, for the
same reason the palette derives from `primitive_catalog()` and not a hand list: the editor must never
be a **second authority** on type semantics. The moment core's compatibility grows (a numeric
widening, a directional `Any`, a subtype) a TS copy silently disagrees, and the editor starts allowing
wires `validate` rejects — a composite the canvas calls valid but core won't eval or publish, which is
exactly the I1 failure the architecture exists to prevent. You can't *fetch* a function as data, so
parity means calling core per-check; the call is a trivial pure fn at UI frequency, so cost is a
non-issue. Pay the bridge, keep the authority singular.

## 2. The bridge step

`compatible(src, dst) -> bool` in `holon-wasm`: deserialize the two bare type strings (`"Number"`,
`"Any"`, …) to `WType`, map to core `Type` via the existing `into_core`, delegate to
`holon_core::compatible`. No new string↔type table — it reuses `WType`'s serde + `into_core`, so the
type-name knowledge stays in one place. Tested on both targets (the helper) plus a JS-boundary
crossing.

## 3. The wiring UI step

- **`onConnect`** adds an edge to React Flow's edge state.
- **`isValidConnection(c)`** — the fail-closed gate, run before an edge is allowed:
  1. Resolve the upstream output type — the source node's `data.output` (its handle id is `"out"`).
  2. Resolve the downstream input type — the target node's input port whose name is the target handle
     id, from `data.inputs`.
  3. Return `compatible(srcType, dstType)` — core's answer. Missing either type ⇒ `false` (fail
     closed).
  4. **One source per input** (core's `duplicate_input_edge_rejected`): reject if the target handle
     already has an edge. This is *UI bookkeeping over the editor's own edge state*, not a second
     semantic authority — the editor owns its edges, and core's `validate` remains the real gate at
     projection. Rejecting (not silently replacing) keeps it fail-closed; delete the old wire to
     rewire.
- React Flow already prevents the rest structurally: a `source` handle only connects to a `target`
  handle (no output→output), and self-connection is disallowed.

The colored ports make all of this **legible before it's enforced**: a legal wire joins two ports of
one hue, or one of them is slate `Any`; a refused drag is two mismatched hues. The type system, made
visible in §4 of the palette L4, now becomes the type *check*.

## 4. Edges as data, not identity

An edge in the canvas is `{ source, sourceHandle, target, targetHandle }` — node-local ids and port
names. Like `position`/`localId`, these are **view-space**: the projection inch (later) turns them
into core `Edge`s addressed by child *index* (`from_child`/`from_port` → `to_child`/`to_port`), and
the visual edge ids never enter a preimage (I5). Wiring this inch is building the graph the projection
will read; it is not yet a composite.

## 5. Scope

This inch: connect nodes, type-checked. **Not** this inch: projecting the wired canvas to a composite
and evaluating it (next — restores the provable `Evaluator` path); editing params; deleting nodes is
whatever React Flow gives for free. Edge rendering is colored by the source port's hue (a small,
honest touch — the wire carries a type).

## 6. What proves what

- **Bridge step:** `compatible` parity on both targets + a JS-boundary crossing — test-confirmed
  (cargo + wasm-pack), a real green count.
- **UI step:** that a legal wire connects and an illegal one is refused is **browser-confirmed** (no
  React test runner in `editor/`), stated plainly. The *rule* it calls is the tested one; only the
  drag-and-drop wiring around it is visual.

## 7. Invariants

I1 — the wire-time check is core's rule, never a TS copy. §5 — monomorphic types + the single `Any`
escape hatch, enforced at the wire. I5 — visual edges are view-space, never identity.
