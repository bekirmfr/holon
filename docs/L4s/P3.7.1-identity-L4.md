# P3.7.1 author-identity — DROPPED (decision record)

**Status: not built, by decision.** This file scoped an identity/crypto/attestation layer
(Ed25519 keypairs, signed attestations over hashes, a `Signer`/`verify_attestation` primitive).
On review it is **over-engineering against this system's own thesis**, and we are dropping it.
The detailed design is preserved below the line only as the *shape it would have to take if ever
revisited* — not as planned work.

## Why drop it

The radical bet of the whole system is **trust from verifiability, not from identity.**
Content-addressing + purity + totality means you never have to trust anyone: you *inspect* a unit
(I9) and you *verify* a result by re-running it (P3.3.2), and totality guarantees the check
terminates while determinism makes it decisive. Identity is what you reach for *when verification
fails or is too costly.* In a system where verification always works, reaching for identity is
**hedging against your own foundation** — and trust/identity/reputation/gatekeeping are exactly the
machinery of systems that *cannot* let you check for yourself. An open, free market is precisely
what avoids those gatekeepers. So identity cut against the point.

The three motivations all dissolve **identity-free**:

- **Sybil-resistance of adoption** → **recursive weighting** (a citation counts in proportion to the
  citer's own adoption; junk referrers nobody builds on contribute ≈0). A property of the content
  graph. No identity. And adoption is an advisory hint, not a gate — low-stakes to game.
- **Result-trust ("skip compute on a stranger's word")** → results are **objectively verifiable**, so
  a wrong result is caught by anyone who checks, *no matter how many keys signed it*. The real (and
  narrow) problem is only "this computation is expensive enough that re-verifying is also expensive,"
  whose trustless answer is a **validity proof** (zk — still "truth in the content") or, for the
  common case, **re-verification / spot-checking**. Sign-and-burn-on-lying is *one* mechanism, but
  neither necessary nor the most aligned, and it only bites for expensive computations in a mature
  market that does not exist yet.
- **Authorship / author-reputation** → the unit **speaks for itself** (fully inspectable). Credit is
  a social nicety; quality-judgment-by-reputation is a crutch for the unverifiable, which here is a
  thin sliver.

**The open free market needs zero identity to be open and free:** publish with no gatekeeper, inspect
anything, verify any result, fork and build on anything, discover by adoption — all present, all
identity-free. The one genuinely missing piece is **transport** (P3.8.2, networked CAS): content and
verifiable results flowing between strangers — which *also* needs no identity (fetch by hash, verify
by re-hash; fetch a result, verify by re-execution; the cheap `entry_key` check is already waiting).

## The one principle preserved (if identity is ever revisited)

Should a real need ever appear, identity must be **optional, external, an attestation _over_ hashes,
never in the preimage** — the unit stays pure content (I5, universal memoization intact), the core
stays **identity-free and trustless**, and a signature is just one more thing *anyone can verify*,
never something a trusted authority *asserts*. No CA, no PKI, no issuer. That constraint is the only
salvage from the design below.

## (Archived) the shape it would have taken

Self-sovereign Ed25519 pubkey = an author (no issuer). An `Attestation {author, subject: Hash,
signature}` is a signed claim "P vouches for hash H," verifiable by anyone; the unit's hash is
untouched (authorship external, not in the preimage). `verify_attestation` pure; `Signer` holds the
secret (a `SecretAccess`-flavored, host-only op). Host-only; core unchanged. **Honest limit that
helped kill it:** identity ≠ Sybil-resistance (keys are free to mint) — it gives only accountability
+ distinct-key counting, and the system already gets what it needs from verifiability.
