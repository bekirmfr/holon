# P4.1 — Projection (canvas → composite) · Level-4 design

> **Companion to `PLAN.md`.** The step that turns the visual graph into a real, hashed core
> `Unit` — the "provable path." The canvas already places typed nodes and type-checks wires;
> projection assembles them into a composite via core's `default_spec` + `derive_and_freeze`
> and shows its content hash. **Pre:** P4.1 wiring (canvas + `compatible`), P1.5.1
> (encapsulation), P4.2c (construction bridge). **Inv:** I1 (the composite is a real unit),
> I5 (cosmetics excluded from identity), §5 (validation at projection). **Effort:** M.

---

## 0. The decision that matters: the editor assembles, the core derives

The design doc names this seam: *the cosmetic/structural boundary lives in P4's projection* —
moving a node changes the editor model but **not** the hash. So projection splits cleanly:

- **The editor assembles** the structural inputs core needs — children (by index) and inner
  edges (by index) — stripping view-only `id`/`position`. This is pure data marshalling: node
  ids → child indices, handle **names** → port **indices**.
- **The core derives** everything that is identity or interface — which inputs promote, the
  exposed output, the `BOUNDARY` edges, the types, and the validation verdict — through
  `default_spec` + `derive_and_freeze`. The editor never recomputes any of it (one decider).

Child-order canonicalization (done) is what makes the editor's arbitrary index assignment
safe: two index orderings of the same graph hash identically, so a cosmetic move can't move
the hash. That inch was pulled forward for exactly this moment.

---

## 1. Grounding: what exists, and the one missing piece

Core (P1.5.1, done) already provides the whole mechanism:

```rust
pub fn default_spec(children: &[Hash], inner_edges: &[Edge], resolver: &impl Resolver)
    -> Result<EncapSpec, EncapError>;                       // canonical proposal
pub fn derive_and_freeze(children: Vec<Hash>, inner_edges: Vec<Edge>, spec: &EncapSpec,
    resolver: &impl Resolver) -> Result<Unit, EncapError>;  // derive types + BOUNDARY edges, validate, freeze
```

Both take a **resolver** (to look up each child's port types) and children **as hashes**.
`EncapError::AmbiguousDefaultOutput` already exists for the "two un-consumed outputs" case.

The bridge exposes `build_preimage`, `Evaluator.insert/eval`, `compatible`, `primitive_catalog`,
`hash_unit_hex` — but **nothing for encapsulation**. That is the single new piece this inch adds.

---

## 2. The bridge method

```rust
// on Evaluator (it owns the MapResolver default_spec/derive_and_freeze need)
pub fn project(&self, children: Vec<String>, edges: JsValue) -> Result<JsValue, JsValue>
```

- `children`: hex hashes of the placed nodes — **already inserted** via `Evaluator.insert`, so
  `self`'s resolver can resolve them.
- `edges`: the inner `WEdge[]` (child→child only), deserialized to `Vec<Edge>`.
- Body: `parse_hash` each child → `Vec<Hash>`; `default_spec(&children, &edges, &self.resolver)?`
  → `derive_and_freeze(children, edges, &spec, &self.resolver)?` → the composite `Unit` →
  `WUnit::from_core` → `JsValue`.
- On any `EncapError`, return `Err` (wasm-bindgen throws): the editor catches and renders it —
  fail closed. `AmbiguousDefaultOutput` and validation failures (cycle, duplicate source, type
  mismatch — the checks the wiring inch deferred to "projection's job") all surface here.

**Why combined (not the split `default_spec`/`derive_and_freeze`):** for whole-graph projection
the canonical proposal *is* the boundary; there is no choosing yet. Exposing the split — so the
UI can reorder/rename promoted inputs or pick the output — is earned by the encapsulation-UX
inch (P4.3), not now. Smallest first.

**Why it returns a `WUnit`, not just a hash:** the editor hashes it through the existing
`build_preimage` + `hash_unit_hex` path (no new hashing surface), and the returned composite
already carries its **derived interface** (promoted inputs, output) — which the next inch (live
eval) and later inspection both want. `project` does only the thing core uniquely owns.

## 3. The editor pipeline (`App.tsx` / `holon.ts`)

On a "Project" action (on-demand — see §4):

1. **Index the nodes.** Enumerate canvas nodes → a `nodeId → childIndex` map (any order; core
   canonicalizes). Keep `id`/`position` out of everything below.
2. **Insert each node.** Build its primitive `WUnit` from the catalog data → `build_preimage`
   → `Evaluator.insert` → hex. `children[childIndex] = hex`. (Pins each atom by hash, I3, and
   populates the resolver so step 4 can resolve them.)
3. **Map the edges.** For each canvas edge `{source, sourceHandle, target, targetHandle}`:
   `from_child = idx[source]`, `from_port =` index of `sourceHandle` in the source node's output
   ports (0, single output today), `to_child = idx[target]`, `to_port =` index of `targetHandle`
   in the **target node's `inputs`** (the editor holds the catalog interface, so name→index is a
   local lookup). → `WEdge { from_child, from_port, to_child, to_port }`.
4. **Project.** `evaluator.project(children, edges)` → composite `WUnit` (core derives the
   boundary) — or a thrown `EncapError` the UI renders.
5. **Hash + show.** `hash_unit_hex(build_preimage(composite))` → display the composite's hash
   (and, cheaply, its derived input/output interface). Live eval is the next inch.

Steps 1–3 are pure TS marshalling; step 4 is the one core call; step 5 reuses existing surface.

---

## 4. On-demand, and the invariant it makes visible

A "Project" button (not live-on-every-change — that's a render nicety for later). The action
makes the load-bearing invariant directly testable by hand:

- Build a graph → a hash appears.
- **Move a node** → re-project → **same hash** (position is cosmetic; I5).
- **Rewire, or add/remove a node** → the hash **changes** (structure is identity).

That is the L3 test for P4.1.1 — *a cosmetic move changes the editor model but not the projected
hash* — turned into something you can see.

---

## 5. Tests

- **+1 native parity** (`project_native`): a fixed `(children, edges)` → `project` equals
  `derive_and_freeze(.., default_spec(..), ..)` and hashes to the expected composite. This pins
  that the bridge method is exactly core's two calls, nothing reimplemented.
- **+1 wasm parity** (`project_wasm` / `project_crosses_js_boundary`): same `(children, edges)`
  across the JS boundary yields the same composite hash as native — the bit-identical guarantee.
- **Browser-confirmed** (no React test runner): the cosmetic-move-invariance and the
  rewire-changes-hash behavior from §4; an ambiguous-output graph shows the error, not a guess.

Baseline **207 native / 10 wasm-target** + the two parity tests. Core and host unchanged — this
is bridge + editor only.

---

## 6. Scope / deferred (recorded)

- **Param editing.** Placed nodes carry the catalog's default params (e.g. `const`'s default
  value). Editing them is the inch after live eval — not here.
- **Boundary choice UX** (reorder/rename promoted inputs, pick the exposed output when ambiguous)
  → P4.3, via the *split* `default_spec`/`derive_and_freeze` surface. This inch only consumes the
  canonical proposal; ambiguity is surfaced as an error, never auto-resolved (no heuristic
  control over a systemic choice).
- **Higher-order `fn` wiring** (a `map`/`fold` node referencing another unit by hash) is its own
  composition concern; a first-order graph is the target here.
- **Live eval through `Evaluator`** is the very next inch — `project` already returns the
  composite the evaluator will run.

## 7. The inch loop

1. Add `Evaluator::project` (holon-wasm) = `default_spec` then `derive_and_freeze` over `self`'s
   resolver, returning the composite `WUnit` (or throwing `EncapError`).
2. Wire `App.tsx`: index map → insert nodes → index-mapped edges → `project` → show hash / error.
3. `cargo test --workspace` + `wasm-pack test --node` → **209 native / 12 wasm-target** (the two
   new parity tests); `tsc`/`tsc -b` clean.
4. Browser-confirm §4 (move = same hash; rewire = new hash; ambiguous = error).
5. JOURNAL + PLAN update; then live eval.
