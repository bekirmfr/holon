# P3.3.1 — Local memoization (the cache thesis, made real) · L4 design note

## What this inch is

The first inch where the project's central claim stops being architecture and becomes a
working mechanism. The thesis (§8, the moat): **a pure, content-pinned unit is a function
from inputs to output that never changes**, so its result is cacheable — keyed by
`(unit-hash, inputs)` — and re-servable without re-evaluation. Local memo builds exactly
that: before evaluating a pure unit, check whether *this hash* has already produced an output
for *these inputs*; on a hit, serve it without re-running.

Totality (every composite halts — `select`+`fold`, no `while`, §13) is what makes this safe:
a memo lookup can never be asked to confirm a result that might not exist.

## The cache key is itself a content hash

`key = BLAKE3( unit_hash ‖ canonical_encode(inputs) )`.

This mirrors the whole system: the cache key is a content hash of *(unit, inputs)*, just as a
unit's identity is a content hash of its structure. Two consequences:

- **The resolver does not enter the key.** A pure unit's `unit_hash` already captures its
  *entire transitive closure* (I6) — same hash ⇒ same children ⇒ same behaviour, on any
  machine, under any resolver. So `(unit_hash, inputs)` fully determines the output. This is
  the content-addressing payoff cashed out: identity already encodes everything that affects
  the result.
- **Local and networked keys are identical.** The same derivation will key a shared,
  trustless cache (P3.3.2) — anyone who computes this key for this unit and these inputs gets
  the same key, so a result one party computed, another can look up and *verify* by
  re-hashing. The local cache is the same mechanism with an audience of one.

So the cache is, precisely, **a state cell keyed by a content hash** — which is the recursion
the design keeps noting (the OS's universal donor, §7, storing the language's pure results).

## The genuinely new piece: a canonical `Value` encoder

`Value` deliberately derives only `PartialEq` — **not** `Eq`/`Hash` — because it carries an
`f64` (no total order, `NaN ≠ NaN`, signed zero) and nested structure. So "are these two
inputs the same input, for caching?" is not a free derive; it is a **canonicalization
decision**. The encoder produces deterministic bytes such that *inputs eval treats identically
encode identically* — the I2 (determinism) guarantee, now at the value layer.

It mirrors the preimage encoder's discipline exactly: **tagged, `u32`-LE length-prefixed,
collision-free** (so a `Number 0`, a `Boolean false`, and an empty `Text` can never collide).

| `Value` case | canonical encoding | the decision |
|---|---|---|
| `Number(f64)` | tag `1` ‖ 8 bytes (LE) of a **canonical bit pattern** | the only hazardous case — see below |
| `Boolean(b)` | tag `2` ‖ 1 byte (`0`/`1`) | trivial |
| `Text(s)` | tag `3` ‖ `u32`-LE byte-len ‖ UTF-8 bytes | **byte-exact, no Unicode normalization** — `Text` is opaque (§13), so precomposed vs decomposed `é` are different Texts (eval treats them as different), hence different keys |
| `List(xs)` | tag `4` ‖ `u32`-LE count ‖ each element recursively | order significant (`[1,2] ≠ [2,1]`) |
| `Effect{sink,payload}` | tag `5` ‖ sink (len-prefixed) ‖ payload (recursive) | effects can be inputs (a `select` or `List` of them); the sink *name* is what the system keys on everywhere |

Input slots are `Option<Value>` (eval's signature; `None` = absent). Encode `None` as a tag
distinct from `Some` (e.g. `0` vs `1 ‖ encode(v)`), so an absent input never collides with a
present one. The whole input list is `u32`-LE count-prefixed.

### The `f64` canonicalization (the heart of the decision, an I2 matter)

`const` rejects non-finite literals (`is_finite_number`), so `NaN`/`inf` can't *enter* as a
literal — but they are still **reachable as computed values**: finite × finite can overflow to
`inf` (`1e308 * 1e308`), and `inf − inf` is `NaN`. So the encoder must handle them, and must do
so deterministically. Three sub-decisions:

1. **`NaN` → one canonical bit pattern.** `f64::NAN` has many bit patterns; collapse them all
   to a single fixed encoding. **Sound** because eval treats every `NaN` identically — IEEE
   arithmetic propagates `NaN` regardless of payload bits, and every comparison with `NaN` is
   well-defined and payload-agnostic. So all `NaN` inputs *do* produce the same output ⇒ they
   *should* share one cache key.
2. **`-0.0` and `+0.0` → the same encoding** (canonical `+0.0` bits). `-0.0 == +0.0` in `f64`
   and eval treats them equally (`compare` says equal; arithmetic agrees), so they must key
   identically. (Naively `(-0.0).to_bits() ≠ (0.0).to_bits()`, so this needs an explicit
   `if x == 0.0 { 0 }`.)
3. **everything else → `x.to_bits()` (LE).** Distinct finite values (and `±inf`) keep distinct
   encodings.

This is the same I2 reasoning as the locale-free casing call in R2: collapse exactly the
representational quirks that don't affect eval's behaviour, and nothing else.

## Where it lives — the FCIS split

- **Core (pure):** the canonical encoder + `memo_key(unit_hash, inputs) -> Hash`. This is the
  new, decision-heavy, *pure* piece — referentially transparent, no state, no I/O. Natural home:
  a new `memo.rs` (or fold the encoder next to the preimage encoder in `hash.rs`).
- **Host (state):** the cache itself — a state cell — and the memoizing eval wrapper. The cache
  mutates (insert on miss); per FCIS that mutable state belongs in the shell, and it matches the
  thesis (the cache *is* a state cell). Shape: `Memo { cache: BTreeMap<Hash, Value> }` with
  `eval(&mut self, unit, inputs, resolver) -> Option<Value>`.

The wrapper:
```
fn eval(&mut self, unit, inputs, resolver) -> Option<Value> {
    if capabilities(unit, resolver).is_pure() {        // soundness guard (below)
        let key = memo_key(&hash_unit(unit)?, inputs);
        if let Some(hit) = self.cache.get(&key) { return Some(hit.clone()); }
        let out = eval(unit, inputs, resolver)?;
        self.cache.insert(key, out.clone());
        Some(out)
    } else {
        eval(unit, inputs, resolver)                   // impure ⇒ never cached
    }
}
```

### Soundness guard: only `is_pure` units (∅ caps)

Memoization is sound **only** for a unit whose output is a pure function of its inputs — i.e.
`capabilities(unit).is_pure()` (the empty manifest). Not `is_replayable` (which permits
drivers): a `clock`/`random` driver's output is *not* a function of its inputs (it varies per
call), so a cached value would be stale; and a `egress`/`store_write` sink *performs* — serving
a cached value would silently skip the effect. So the guard is the strict `is_pure`, and an
impure unit simply falls through to ordinary `eval`, uncached.

## Forks (surfaced; recommendations are not yet decisions)

- **F1 — `NaN`: canonicalize vs refuse to memo. → canonicalize.** Sound (above), and simpler
  than scanning inputs to bail. Refusing would also leak an asymmetry (some pure evals
  uncacheable for an invisible reason).
- **F2 — key = hash-of-bytes vs the raw bytes. → hash (a `Hash`).** A fixed 32-byte key,
  networked-ready (identical derivation everywhere), and consistent with content-addressing.
  Raw bytes would key a local map fine but wouldn't carry to the shared cache cleanly.
- **F3 — cache stores `Value` vs encoded bytes. → `Value` (in-memory).** The encoder is for the
  *key*; the stored *output* is just a `Value` clone for now. Encoding the output for a
  persistent/networked cache is a later inch.
- **F4 — guard = `is_pure` vs `is_replayable`. → `is_pure`.** (Reasoned above — drivers vary,
  sinks perform.)
- **F5 — scope: top-level only vs recursive per-node. → top-level for P3.3.1.** Memoize the root
  pure unit's `(hash, inputs) → output`. Recursive sub-node memoization (caching every pure
  composite child during one eval) is a real optimization but a separate, larger inch; the
  honest cost of top-level-only is that repeated *sub*-evaluations within one call aren't shared
  yet.

## What this inch deliberately does NOT do

- No persistence (in-memory cache; a published/persistent memo store is a later inch — it needs
  the output encoded too, F3).
- No networking / no shared cache (P3.3.2, the actual differentiator, still deferred).
- No recursive per-node memo (F5), no eviction / size bound.

## Tests (what green must prove)

**Encoder (core):**
1. **determinism** — the same `Value` encodes to the same bytes twice.
2. **signed zero** — `Number(-0.0)` and `Number(0.0)` encode identically.
3. **NaN canonical** — two different `NaN` bit patterns encode identically (and distinctly from
   any finite/`inf`).
4. **no collisions across types** — `Number(0.0)`, `Boolean(false)`, `Text("")`, empty `List`
   all encode distinctly (tag + length prefixes do their job).
5. **nesting** — a `List` of mixed `Value`s round-trips deterministically; `[1,2] ≠ [2,1]`.

**Memo (host):**
6. **hit** — a pure unit evaluated twice with the same inputs is cached: second call returns the
   same result and (observably) does not re-eval. *(Make re-eval observable — e.g. assert the
   cache now holds the key, or use a counting resolver.)*
7. **miss on different inputs** — same unit, different inputs ⇒ two cache entries, both correct.
8. **impure is not cached** — a `clock`/`random` or `egress`-bearing unit is not stored (falls
   through to plain eval); the cache stays empty for it.

Expected: a new core `memo.rs` (≈5 encoder tests) + a host `Memo` (≈3 tests). Core grows;
host grows.

## Why this is the right next inch

It is the smallest thing that turns the moat from a property into a mechanism. Everything it
needs already exists and is green — purity classification (`is_pure`), content-addressing
(`hash_unit`), totality (so lookups are always well-founded), and the preimage encoder as the
template for canonical bytes. The one new decision — what makes two inputs "the same" — is the
`f64` canonicalization, and it is the same I2 reasoning the project has already applied twice
(locale-free casing, finite-only `const`). The cache being a state cell keyed by a content hash
closes the loop the design has been pointing at all along.
