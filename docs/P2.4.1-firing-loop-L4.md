# P2.4.1 — Eager effect-firing loop · Level-4 design (rev. 2)

> *crate:* design-mode mechanism is **pure `holon-core`**; deploy shell is
> **holon-host** · *pre:* P1.4.3, P2.1.1, P2.3.x · *co-builds:* a minimal **P2.7.1**
> (mock declaration) · *inv:* `§6` / `I7` / `I5` / `I8` · *effort:* **M**
> *References rows:* P2.4 (FCIS / Roc / FRP; **refuse debounce**), P2.7 (simulation doubles).

**Revision note.** The firing mechanism is now a **substituting resolver** (design
mode) plus a thin **deploy shell**, after the insight that an effectful leaf must
declare a *pure mock* the core can evaluate. That insight is not a testing
convenience bolted on later — it is *what lets the effect layer be run at all*: an
`email` leaf has no pure `compute`, so without a pure stand-in there is nothing for
`eval` to run. The old §2 fork (graph-surgery α vs boundary-promotion α′) is resolved:
**α′ is demoted** from "the firing mechanism" to "one option for deploy-time sink
observation," and substitution-via-resolver becomes the frame.

---

## 0. The decision that matters: the host never evaluates

Design firing **is** core `eval` run against a *substituting resolver*; deploy firing
wraps the **edges** of core `eval`. In neither does anything re-implement evaluation.

This is the strongest possible form of the one-decider rule (P4.2 / I5): in design
mode the core does not even know a mode exists — it is resolving hashes and running
units exactly as always; the *resolver* is the only thing that differs. The editor's
WASM `eval` and the host's native `eval` remain bit-identical, so I5 holds and the
P3.3 cache stays sound. **The host sources, swaps a resolver, or dispatches — it never
evaluates.**

---

## 1. The eager round

```
trigger ─▶ source inputs ─▶ eval settles the closure ─▶ dispatch settled values
            (mock or real)     (core — the one decider)      (mock-pure, or real IO)
```

Eager ⟹ quiescence is free: `eval` *returns* the settled value before anything is
dispatched, so no sink observes a mid-propagation transient — there is nothing to
debounce. For an acyclic graph the fixed point **is** a single `eval` pass (eval is
topological), so each node — including each sink — is visited **exactly once with its
settled input**. "Fire once with the committed value, no mid-propagation fire" is thus
`eval`'s existing single-pass guarantee, not new machinery. The settle/commit gate of
§6 only bites in the async future (P2.4.2); refuse a debounce/sleep here.

---

## 2. The firing frame: a substituting resolver

`eval` already resolves every child by hash to a `Unit` before running it. So the
substitution point is the **resolver** — no graph surgery, no `eval` change, no
authoring constraint:

> A **substituting resolver** wraps the real resolver. On `resolve(hash)`, if the real
> unit is an effect leaf (`kind_of(name) != Pure`), it returns that leaf's **pure
> mock** instead of the effect primitive. Core `eval` runs the whole closure, none the
> wiser; the mock is itself a pure holon, so it rides the same indirection as
> everything else.

- **Any depth.** The swap happens at resolve time, so an effect leaf buried ten levels
  down is substituted like any other. This *matches* the capability layer (effects
  surface at any depth) instead of forcing them to the edges the way α′ did.
- **Mocks are interface-compatible.** A mock must carry the same ports as the leaf it
  replaces, so surrounding edges still wire.
- **α′, demoted.** `resolve` returns *structure*, never performs IO — so it cannot
  *fire* a real sink. A real buried sink's settled input must instead be **observed
  after `eval`** (deploy mode, §4). α′ ("author sinks at the boundary so their inputs
  are `eval` outputs") becomes *one option* for that observation, alongside taps and
  multi-output, and is deferred with real IO.

*Build wrinkle (noted, not solved here):* `Resolver::resolve` returns `&Unit`, so the
substituting resolver must **own** the mocks it hands out — a `BTreeMap<Hash, Unit>`
mapping each effect-leaf hash in the closure to its mock, built by one closure pre-pass,
with `resolve` checking that map before delegating to the real resolver.

---

## 3. The two modes

**Design / test mode — buildable now, and it is pure `holon-core`.** A mock-substituting
resolver + core `eval`. The whole run is pure: deterministic, replayable, and —
because it is pure and content-keyed — **memoizable by `(closure-hash, input-hash)`**
like everything else. Testing a service becomes cached pure evaluation. Notably this
keeps the buildable part of firing *in the pure core* (`mock_of` + the substituting
resolver + design-`eval`); only deploy crosses the seam.

**Deploy mode — deferred with real IO.** The `holon-host` shell: source real driver
events (substituted in as value-units, the input side), `eval` the closure, then
**observe** the settled values flowing into sinks and **fire** real effects (the output
side). This is the `Host` / `drive` / `emit` seam — the only place real IO lives, and
the only place α′-style sink observation matters.

**The state wrinkle (made explicit).** "Returns pure results" is clean for drivers (a
pure scripted/constant value) and sinks (a pure function of input: absorb → plausible
result). A **state cell is the exception** — it is *not* a pure function across firings,
because the value it returns this round depends on what was written last round. So a
state mock cannot be a standalone pure unit; it is **host-threaded ephemeral memory**:
a state-**read** is substituted with the current value the host supplies (input side), a
state-**write** is observed after `eval` and persisted (output side), threaded across
rounds in *both* modes. That is exactly why **P2.6.1 is its own leaf** rather than
folding into the mock mechanism.

---

## 4. The guardrail — now a hard rule, not a hope

The substituting resolver is precisely the laundering surface P2.7.2 guards. Made
concrete:

> **`capabilities()` / `effects_of()` always take the REAL resolver; only design-mode
> `eval` ever sees the MOCK one.** Two resolvers, two questions, never crossed.

A malicious unit shipping a benign mock around a real `NetworkEgress` still surfaces
the egress in its manifest — because the manifest is computed from the *real* leaf, by
a classification path that never consults `mock_of`. Simulating innocent buys nothing
at the trust boundary. *Design mode tests your wiring; the capability surface lets you
trust the unit.* And because the mock is substituted at resolve time, it is **never in
any content hash**.

---

## 5. Prior art & divergence

- **FCIS / Roc platforms** — host owns effects, interior is pure. Deploy mode is the
  shell; `eval` is the core. Ported.
- **P2.7.2 design/deploy modes** — this *is* that mechanism, pulled to where it was
  always needed: the mock is what makes an effect leaf evaluable.
- **FRP height/topological propagation** — the reference for the **async** future
  (P2.4.2); the eager DAG needs none of it (single pass = fixed point).
- **Diverge: refuse debounce/sleep** — settle-before-fire is eager *ordering*, never a
  timer.

---

## 6. Sub-leaves (build order)

1. **Minimal P2.7.1 — `mock_of(name) -> Option<Unit>`** *(core)* — a pure,
   interface-compatible mock per effect leaf (`timer` ⇒ a constant value; `email` ⇒ a
   pure absorb→confirmation). `store` is the state exception (no standalone pure mock).
   Lives beside `capabilities_of` in `kind.rs`; **never consulted by classification.**
2. **Substituting resolver** *(core)* — a pure `Resolver` impl owning a
   `Hash → mock Unit` map built by one closure pre-pass; swaps effect leaves for mocks.
3. **Design-mode firing** *(core)* — = `eval(service, inputs, &substituting_resolver)`.
   No new evaluator; the "loop" is `eval`.
4. **Deploy shell** *(host, deferred with real IO)* — `Host` / `drive` / `emit`, real
   sink observation; state threading lands with **P2.6.1**.

So the buildable-now inch is **pure core**: `mock_of` + the substituting resolver +
design-mode tests. The host crossing waits for deploy/real-IO.

---

## 7. Tests (the proofs)

- `design_run_is_pure_and_deterministic` — a `driver→double→sink` service evaluated
  through the substituting resolver yields a value; re-running is identical; it equals
  core `eval` over the mock-substituted closure (one decider).
- `sink_mock_sees_settled_value_once` — eval's single pass visits the sink mock exactly
  once, with the settled input (fire-once / no-transient, demonstrated purely).
- `effect_leaf_at_depth_is_substituted` — an effect leaf buried in a composite is
  swapped by the resolver (depth-agnostic), where α′ could not reach.
- `classification_ignores_mocks` *(the guardrail)* — `capabilities()` over the **real**
  resolver still reports the real leaf's manifest even when a benign mock exists; the
  mock changes no hash.

---

## 8. Deferred forks (recorded)

- **Deploy shell / real sink firing** — the `Host` seam, real IO, and post-`eval` sink
  observation (α′ / taps / multi-output as observation options). With real IO.
- **State cell** → **P2.6.1** — host-threaded value; read substituted, write observed.
- **Full P2.7** — every effectful primitive's mock, custom session stimuli, mode-aware
  deploy (P2.7.2). Here only a minimal `mock_of` for exemplars.
- **Multiple / continuous drivers, scheduling, ordering** — reactive; one round per
  trigger now.
- **Async + autonomous cells + settle/commit gate** → **P2.4.2** (eager makes it
  unnecessary).
- **Correlation token** → **P2.5.1**; **idempotency key** → **P2.5.2**.
