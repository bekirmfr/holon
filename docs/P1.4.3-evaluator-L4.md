# P1.4.3 — Eager Graph Evaluator · Level-4 design

> **Companion to `PLAN.md`.** Detailed design for the load-bearing leaf — the one that
> closes the "identity but not evaluation" gap.
> **Pre:** P1.4.1 (Value), P1.4.2 (primitives), P1.3.1 (validation — guarantees a typed,
> acyclic graph). **Inv:** I1 (parity), I2 (purity), I3 (by-reference). **Effort:** L.

---

## 0. The one decision that matters: the firing rule *splits*

The §6 per-input policies — *required / optional* and *consume / persist / default* — do
**not** all belong in the pure core. Descending the leaf forces the split, and it is the
central L4 result:

- **`required` / `optional`** — pure. Whether an input must be present is a property of
  the computation, not of time. **In.**
- **`default(X)`** — pure. A constant fallback for an absent optional input. **In.**
- **`persist` (port keeps its last value)** — gives a port *memory across firings*, which
  §6 says forfeits the purity theorems. It is an implicit state cell. **Out of the pure
  core** — it belongs at the state boundary.
- **`consume` (token nulled after firing, must be refilled)** — presupposes discrete
  firing *rounds* and tokens, which the eager fixed-point model does not have and must
  not grow. **Out** — it belongs to the async/autonomous-cell firing model (P2.4.2).

So the **pure eager firing rule** is exactly:

> A node yields `Some(value)` iff **all its `required` inputs are present**; otherwise it
> yields `None`. `optional` inputs contribute their value, their `default`, or absence,
> per the primitive's `compute`.

This keeps P1.4.3 genuinely pure — no port memory, no rounds — and *places* (does not
delete) `consume`/`persist` where they become meaningful: the state boundary and the
async firing model. This is "effects/state at the edges" applied to the firing rule itself.

## 1. Evaluation model

- **Signature:** `eval(unit, inputs, ctx) -> Option<Value>`. A node's result is
  `Option<Value>` — `None` = "not computable this evaluation" — and `None` **propagates**
  (a downstream node with an unsatisfied `required` input is itself `None`).
- **Single output** (port 0). Multi-output composites are a recorded deferral (design
  doc §9); the `Edge.from_port` field already allows it structurally for later.
- **Primitive:** dispatch on the primitive's name → its native `compute(gathered, params,
  ctx)`.
- **Composite:** resolve the inner DAG —
  1. **topological sort** of the children (deterministic; ties broken by child index),
  2. a **local scratch** `Vec<Option<Value>>` indexed by child index (each composite
     evaluation gets its own — so nested composites and repeated instances never collide),
  3. **inject** the composite's external input values at the promoted inner ports (via the
     promotion map frozen at encapsulation),
  4. evaluate children in topological order, writing into the scratch,
  5. **read** the exposed output (the unconsumed inner output),
  6. **recurse** when a child is itself a composite.
- **Eager strategy:** a **single topological pass** computes the fixed point. Acyclicity
  (guaranteed by P1.3.1) means one pass suffices — **no iteration, no repeated passes**.
  (The throwaway prototype looped `n` passes as a shortcut; the real evaluator sorts.)
- **Polymorphism is free at eval time.** `any`-typed primitives (`Select`, `Get`, `Map`)
  need no special handling — runtime `Value`s carry their own type, and wire-time type
  soundness was already established by P1.3.1.

## 2. Resolver — children are referenced by hash

Composites reference children **by 32-byte hash** (content addressing). So the evaluator
needs to turn a hash into a definition:

```
trait Resolver { fn resolve(&self, hash: &Hash) -> Option<&Unit>; }
```

- **Phase A:** an in-memory `Resolver` (a `BTreeMap<Hash, Unit>`), populated as units are
  built. Deterministic iteration; no IO.
- **Later:** the on-disk content-addressed store (P3.8.1) is just another `Resolver`
  implementation behind the identical trait. The evaluator never changes.

This keeps the core pure (resolution is a lookup, not an effect) and makes the store a
drop-in, not a rewrite.

---

## 3. Evaluation context (`ctx`) — for higher-order primitives

`Map` applies a *referenced unit* to each element, so it must be able to resolve a hash
and recursively evaluate. The `ctx` threaded into `compute` carries exactly that:

```
ctx.apply(unit_hash, [element]) -> Option<Value>   // resolve + eval, recursively
```

Only higher-order primitives use `ctx`; first-order primitives ignore it. This is the
Rust form of the prototype's `ctx.apply`, and it is what lets `Map` (and later
`Filter`/`Reduce`) be ordinary primitives rather than engine features.

## 4. Sub-leaves (build order)

| # | sub-leaf | gist |
|---|---|---|
| a | **Resolver** | trait + in-memory impl (`BTreeMap<Hash, Unit>`) |
| b | **Eval skeleton** | `eval → Option<Value>`; `None` propagation |
| c | **Input policies** | `required / optional / default`; *exclude* consume/persist; extends `Port` encoding (see §6) |
| d | **Primitive dispatch + ctx** | name→`compute`; thread `ctx` for `Map` |
| e | **Composite resolution** | topo sort, scratch, promoted-input injection, recursion |
| f | **Determinism** | stable topo order (tie-break by index); ordered structures only |

## 5. Tests (the proofs this leaf is done)

- **Primitive:** `Add[3,7,5] = 15`; `Compare(72,70,">") = true`.
- **Composite (the v3 seed, ported):** `List(3,7,5) → Map(Double) → [6,14,10]`; and
  `List(3,7,5) → Sum → 15`.
- **Nested composite:** a composite containing a composite evaluates correctly.
- **`None` propagation:** a missing `required` input yields `None` downstream.
- **Default:** an absent optional input uses its `default`.
- **Interface parity (discharges P1.2.1):** swap a primitive for an equivalent composite
  in a host graph → identical result, evaluated through the identical path.
- **Determinism (feeds P1.4.4):** repeated evaluation of one graph yields identical bytes.

---

## 6. Encoding impact (coordinates with P1.5.2)

Adding an input policy (`required | optional{default}`) to a `Port` is a **structural**
change — it affects the computed result, so it is **in the hash**. The `Port` encoding
gains a policy field (tagged, length-prefixed, like the rest). Nothing is published yet,
so there is no migration; the `ENCODING_VERSION` byte already in the preimage covers the
evolution. This touches the same canonical encoder that P1.5.2 (param promotion) will
extend — worth doing them with the encoder's invariants (determinism, domain separation)
in view together.

## 7. Deferred sub-forks (recorded, not built)

- **Multi-output composites** — single output (port 0) for now; `from_port` reserves the room.
- **`consume` / `persist` input policies** — async firing model (P2.4.2) and the state
  boundary, where port memory and firing rounds are meaningful.
- **Generics in dispatch** — monomorphic + `any` for now (§5).
