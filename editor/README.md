# Holon editor

The editor surface for Holon — a Vite + React + TypeScript app that runs the **same** core as the
native host and the marketplace, compiled to wasm via `holon-wasm`. It builds units through the one
core encoder (`build_preimage`) and evaluates through the one evaluator (`Evaluator`).

This first commit is an **end-to-end proof**, not the real UI: it builds a `const(7)` node, wires it
to a composite's boundary output, evaluates the graph through the wasm bridge, and renders `7`. React
Flow draws the same two-node graph beside the result so both halves of the stack are visible.

## Prerequisites

- The Rust workspace builds and its tests pass (`cargo test --workspace`).
- `wasm-pack` and the `wasm32-unknown-unknown` target installed (already true if
  `wasm-pack test --node crates/holon-wasm` works).
- Node.js (any recent LTS) and npm.

## Run

From the repository root:

```sh
# 1. Build the wasm package INTO the editor (./editor/wasm). Re-run this whenever the Rust
#    bridge in crates/holon-wasm changes.
cd crates/holon-wasm
wasm-pack build --target web --out-dir ../../editor/wasm
cd ../..

# 2. Install editor deps and start the dev server.
cd editor
npm install
npm run dev
```

Open the URL Vite prints (usually http://localhost:5173). You should see **Result: 7** and a
two-node graph (`const(7)` → `output`).

## Layout

- `src/holon.ts` — the typed facade over the bridge. Its TypeScript types mirror the Rust serde
  types in `crates/holon-wasm/src/lib.rs` exactly (discriminated unions, checked exhaustively).
- `src/App.tsx` — the proof: build → insert → eval, then render.
- `wasm/` — generated by `wasm-pack`; never edited by hand, gitignored, rebuilt from the crate.

## Note on production builds

`npm run dev` needs no wasm plugin (`--target web` loads itself via `init()` + fetch). A production
`vite build` may need `vite-plugin-wasm`; we'll add it when we get there.
